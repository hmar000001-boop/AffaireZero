# Affaire Zéro — Episode 01: The Impossible Absence

A mobile-first, first-person 3D mystery built with Unity 6.3 LTS. The first episode is designed to be playable offline and supports English and Arabic, including a basic Arabic shaping/RTL presentation layer for Unity UGUI.

> **Current deliverable:** a source project / playable vertical slice with a procedurally assembled 3D environment, eight inspectable clues, a case dossier, branching interview responses, an evidence-supported conclusion, local saving, and GitHub Actions Android packaging. The scene and player settings are generated by an Editor bootstrap when Unity imports the project or when the CI build runs.

## Play loop

1. Start the investigation and read the case briefing.
2. Explore the study, hallway, utility room and archive with the on-screen joystick and drag-to-look controls. On desktop, use **WASD** and hold the **right mouse button** to look around.
3. Approach amber evidence markers and tap **Inspect**.
4. Read the collected clues and interview Nora Rahal, Malik Haddad and the missing architect's recorded design statement in the case file.
5. Form a theory by selecting a suspect and at least three collected clues. The game validates that the conclusion links the hidden route, evidence of staging, and independent corroboration.
6. Resolve the case to see the complete explanation.

The eight clues are: the sealed lock, impossible camera, timed footsteps, service panel, plaster dust trail, Elias's plans, concealed hatch, and recovered voice note.

## Open in Unity

1. Install **Unity 6.3 LTS** with **Android Build Support**, Android SDK & NDK Tools, and OpenJDK through Unity Hub.
2. Extract the ZIP and open the `affaire-zero` folder as a Unity project.
3. Wait for package resolution and script compilation. `Assets/Editor/ProjectSetup.cs` creates `Assets/Scenes/Main.unity`, configures Auto Rotation, enables the required input backends, sets the Android application ID, and adds the bootstrap scene to Build Settings.
4. Press Play in the Editor.

This project uses the Built-in Render Pipeline, Unity UGUI, and the Unity Input System package (1.20.1, compatible with Unity 6.3). World geometry and props are created from Unity primitives at runtime; no Asset Store package or external art asset is required.

## Build an Android APK from GitHub — no local computer required

The normal project workflows are under `.github/workflows/`, but GitHub cannot execute a workflow while it is still inside an unextracted ZIP. For a phone-only setup, use the companion file `Affaire_Zero_GitHub_Bootstrap.yml` supplied alongside the project ZIP in the delivery. This bootstrap workflow lets GitHub run the project directly from the archive.

### Phone-only repository setup

1. Create an empty repository on GitHub.
2. Upload the source archive as a single file named exactly `Affaire_Zero_Unity_Project.zip` at the repository root.
3. In GitHub's web editor, create `.github/workflows/affaire-zero-bootstrap.yml` and paste the companion bootstrap workflow file's contents. Commit it to `main`.
4. Open **Actions** and run **Affaire Zero · GitHub mobile bootstrap** with the task `request-license`.
5. Download the `Unity-activation-file` artifact from that run. Follow the current GameCI/Unity Personal license activation instructions to turn the `.alf` into a `.ulf` license file.
6. Under **Settings → Secrets and variables → Actions**, add `UNITY_LICENSE` with the full `.ulf` contents. Add `UNITY_EMAIL` and `UNITY_PASSWORD` only if required by your license setup. Never commit license files or passwords.
7. Run the bootstrap workflow again, selecting `build-apk`. When the build succeeds, download the `AffaireZero-Android-*` artifact; it contains `AffaireZero.apk` and `BuildReport.txt`.

The companion bootstrap workflow is separate from the source archive on purpose: GitHub Actions only discovers workflow files committed under `.github/workflows/` in the repository itself. After you are able to commit the extracted project files as normal repository contents, you can use the project's included `android-apk.yml` for regular push/PR builds.

The APK is unsigned/debug-installable using Unity's default build output. Google Play production signing, the store listing, and real purchase products are separate release steps. This first project version contains one free episode; it does not fake purchases for episodes that do not exist yet.

## Project settings

- Unity editor: `6000.3.27f1` (Unity 6.3 LTS patch)
- Android package ID: `com.affairezero.mystere`
- Initial version: `0.1.0`
- Minimum Android API: 26 (Android 8.0)
- Architecture: ARM64
- Orientation: Auto Rotation, portrait + landscape
- Rendering: Built-in Render Pipeline / Gamma
- Persistence: local PlayerPrefs JSON save; no account or backend
- Network: not needed to play Episode 01

## Scope and known limitations

- The environment and interactable props are procedural 3D assets. They are original in-project geometry, not scanned or photorealistic production art. The look is deliberately atmospheric, modern and low-poly/stylized to keep the APK small and avoid missing licensed assets.
- The Arabic layer includes contextual shaping for common Arabic characters and reverses each line for UGUI's left-to-right renderer. It is a dependency-free starter, not a full Unicode bidirectional text engine; mixed Arabic/Latin text, punctuation edge-cases, ligatures and accessibility typography must be reviewed on real Android devices before public release.
- No Unity Editor or Android toolchain is included in this ZIP, so this environment cannot truthfully certify an APK build, on-device frame rate, touch ergonomics, or the final Arabic font rendering. Run the included workflow/device QA before publishing.
- Only Episode 01 exists in this first release. There is no active paid episode yet, so store purchases/restores and Play Billing are intentionally not faked or wired to nonexistent products. A store adapter and real Unity IAP/Google Play product configuration must be added when a paid episode is ready.
- Before Google Play release: choose and test store signing, create the developer console app, confirm target API requirements, review privacy/data safety declarations, provide tested screenshots/icons, and test on at least one low/mid-range and one high-density Android device.
